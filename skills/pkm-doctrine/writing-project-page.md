# Writing a project page

Start from `templates/project-page.md`, then adapt it to the configured PKM and
task surfaces.

## Top

Write one sentence saying what the project is, then one or two sentences of
current status in plain words. If one thing clearly moves the project, end with
**Next: <that one thing>**—never more than one. Then add `---`.

## Parts

Use one H2 per real part, named in the owner's language. Include only fields
that have content:

- *Status*: what is true now. Assistant work goes here, never as an owner task.
- *To Do*: only when page-native tasks are the authoritative task surface.
  Each task must transcribe an observed owner commitment, be verb-first, and be
  one concrete action. Indent page-native checkboxes two spaces beneath the
  field label. Keep only near-term detail.
- *Waiting*: who owes what, since when, and whether the owner needs to act.
- *Later*: named phases or wishes, one line each, without speculative tasks.

When an external task system is authoritative, omit page-native checkboxes.
Keep execution in that system and put only concise project state or pointers on
the page. (Rule: `task-placement`)

Use bold subparts only when a part genuinely needs its own fields.

## Bottom

Add `---`, then `# Context` as bullets: area, people, sister pages, and key
locations. Put complicated background on its own small page and link it.

## Sparse case

When little is known, say so exactly. Ask one bounded question with its
affordance. Do not create a task unless owner-sourced input already contains
the commitment; a page with no tasks is correct.

## Pre-output check

1. Is every claim supported, with unknowns stated?
2. Is there at most one **Next:**?
3. Does each task come from an observed owner commitment and live only on the
   authoritative task surface?
4. Does each Waiting item state the owner's role?
5. Are empty sections, duplicate task lists, tables unsupported by the active
   surface, and cross-project waiting items absent?

Do not add status suffixes to every heading, create symmetrical empty sections,
duplicate execution, or infer freshness from the page rewrite time.
