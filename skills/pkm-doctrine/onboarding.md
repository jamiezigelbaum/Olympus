# Onboarding a new user

You are meeting someone's life. Elicit; do not scaffold speculatively.

1. **Confirm capabilities first.** Identify the authorized writable PKM
   surface, its assistant-managed-page marker, its restricted-content
   mechanism (if any), and the authoritative task surface. This doctrine
   supplies none of those integrations.
2. **Interview for the registry.** Ask for active projects in the owner's words
   ("what are you trying to finish in the next few months?"), then areas
   ("what do you maintain a standard for?"). Store the registry through the
   configured PKM surface, using its restricted marker only if the registry's
   classification requires it. Do not import a template taxonomy.
3. **Build hubs first.** Link to pages that exist and use plain-text names for
   ones that do not. Materialize a page only when there is something useful to
   say. (Rule: `lazy-materialization`)
4. **Work one page at a time, evidence-first.** Draft from owner-sourced input
   and policy-allowed evidence. When little is known, write a sparse page plus
   one verb-first question with its affordance.
5. **Keep bulk decisions bounded.** If the writable surface supports it, put
   one editable review artifact there with a legend. Otherwise provide one
   bounded review artifact in the available channel; do not scatter a long
   questionnaire through chat.
6. **Configure task placement.** If page-native tasks are authoritative, enable
   that adapter. If another system is authoritative, keep task execution there
   and use PKM pages for context and state, not duplicate checklists. (Rule:
   `task-placement`)
7. **Record corrections from day one.** Use a distinct
   `pkm-doctrine-personal` workspace skill through the installation's approved
   maintenance flow. Stamp this pack's version into the overlay.

## Trust default

Classify each item by its content and owner markings, never by whether it came
from email, a file, or a message. Apply the active surface's restricted
mechanism only when classification requires it. When required protection is
unsupported, keep secure detail off the page and state the limitation instead
of pretending the page is protected. (Rule: `restricted-by-classification`)
